# Hunyuan3D-2.1 inference stack (torch 2.5.1 / cu124 era). Pinned to Tencent's
# own requirements.txt for the pinned repo commit so the shape + PBR paint
# pipelines import and run exactly as upstream verified them. torch/torchvision/
# torchaudio are installed separately in the Dockerfile from the cu124 wheel
# index (they must match the base image's CUDA 12.4).
#
# Deliberately excluded from upstream's list:
#   - gradio: demo UI only.
#   - deepspeed: training-only; its sole import in the shape stack sits inside a
#     training-EMA branch that inference never reaches.
#   - bpy (Blender): a Blender-sized wheel that is only reached through
#     DifferentiableRenderer.mesh_utils.convert_obj_to_glb (the save_glb=True OBJ
#     to GLB exporter). This worker never calls it — it paints with
#     save_glb=False and assembles the final PBR GLB with pygltflib via
#     hy3dpaint.convert_utils.create_glb_with_pbr_materials. The Dockerfile
#     drops a tiny stub `bpy` module so the top-level `import bpy` in
#     mesh_utils resolves; no bpy function is ever executed.
# Added on top: httpx (the SSRF guard in worker_security), google-cloud-storage
# (task state + weight staging + result upload).
