# Feature 19: forge 3D props live inside build mode

The platform's headline capability is text to 3D, and the world's build mode can now use it: the prop palette has a Forge form (and chat takes `/forge <prompt>`), `src/game/forge-prop.js` drives the free draft lane, and the finished GLB rides the uploaded-prop pipeline so everyone in the world sees it and the room persists it ([docs/play-forge-in-world.md](../play-forge-in-world.md)). Since 2026-11-03 the rest has shipped too: the placement-first hologram, the tiered size ceiling, and the server-side abuse limits. At a live event this is the demo moment, and the size ceiling is what keeps it from becoming the iOS crash. This prompt is now the spec to verify against and extend, not a blank build.

## Where the code lives

- Forge lane: `api/forge.js` (`POST /api/forge` submits, `GET /api/forge?job=` polls, `POST /api/forge?action=rig` auto-rigs; there is no separate rig handler) and siblings (`api/forge-gameready.js`, which now also accepts a settled forge purchase and echoes only its own payment error codes, and `api/forge-remesh.js`, whose poll can mirror a finished GLB into first-party storage so a simplified prop passes the room allow-list; the client offers a simplified model only when the server answers `durable: true`); in-world client `src/game/forge-prop.js` plus `src/game/forge-session.js` (job state and this session's history) and `src/game/forge-hologram.js` (the placed hologram; submit, poll every 2.5 s, up to 6 minutes for a cold GPU start, with a "Waking up a GPU" status line from the shared `coldStartLabel` in `src/shared/forge-frames.js` while a worker boots, reference photos via `/api/forge-upload` capped at 8 MB, keyed to the same `forge:cid` handle the /forge page uses so in-world forges land in the same history); page precedents in `src/forge.js` / `src/forge-studio/`. Use the platform's free text-to-3D lane and its existing rate limits; do not add a new paid dependency
- Prop plumbing (already networked and persistent): `src/game/world-objects.js` (`registerUploadedProp`, mirrors the server `objects` MapSchema), `src/game/avatar-upload.js` (`uploadPropModel`, presigned upload), the `_uploadProp` flow in `src/game/coincommunities.js`, persistence via `src/game/world-persist.js`
- Prop palette UI: the props panel in `src/game/coincommunities-ui.js` (the gallery tab still fetches `/api/avatars/public`; the Forge form is `forgeBtn` / `toggleForge()` reporting through the shared status strip, and the game side is `_forgeProp` in `src/game/coincommunities.js`), styles in `src/game/coincommunities.css`
- Size ceiling: `src/game/prop-budget.js` (`propBudget`, `overBudget`, `simplifyTarget`), tiers listed in [docs/play-forge-in-world.md](../play-forge-in-world.md). In-world abuse limits: `api/_lib/forge-world-limits.js`
- The mobile lesson: `src/game/ambient-crowd.js` documents how uncapped user models killed iOS tabs, and its `CROWD_BUDGET` tiers are the sizing precedent
- Generation ground truth when debugging: the `forge_creations` table carries per-generation backend, status, error, and prompt

## What to build

1. **A Forge tab in the prop palette.** Shipped as the Forge form in the props panel (prompt or reference photo, one forge at a time, progress in the status strip) plus the `/forge <prompt>` chat command, which opens build mode with the result armed. The form also lists this session's forges with Place again and Retry, and quotes measured timings (88 s, 92 s and 355 s on production on 2026-11-03, with the draft lane holding the request open, so the card shows real elapsed seconds). Verify the quoted times still match observed behavior.
2. **Placement-first flow.** Shipped: starting a forge arms a hologram, the player aims and drops it while the lane works (real job state on its card, no fake progress), the GLB spawns at that pose with a materialize effect once the room confirms it, and a failure turns the hologram into an error marker with Retry and Dismiss. A forge that finishes before the hologram is placed (a cached prompt) arms the model instead. Verify all three paths.
3. **The full prop pipeline, not a side door.** Shipped: `_forgeProp` hands the finished GLB to `registerUploadedProp` and the normal `obj:spawn` placement, so it is networked to every player, persists like any other build, respects the per-player build budget, and is undoable with the existing Ctrl+Z stack. A result that comes back with `durable: false` (temporary storage the server's asset allow-list may refuse) already raises a warning toast in `_forgeProp`; a room refusal of the asset itself (`asset_url`, `asset_size`) now unregisters the palette entry through the tracked spawn id; verify that no refused placement leaves a phantom.
4. **Size discipline.** Shipped: every result is downloaded and measured (triangles from the GLB, bytes from `Content-Length`) against a tiered ceiling (high 100,000 triangles and 8 MB, medium 60,000 and 6 MB, low 30,000 and 3 MB, touch devices one tier down), simplified through `/api/forge-remesh` when over, and rejected with a message stating its size if it still does not fit. Nothing is placed raw. The room separately refuses any model over 8 MB. Verify with an intentionally heavy prompt.
5. **Abuse limits.** Shipped on `POST /api/forge` when a `world` is sent: a per-player cooldown and a per-world admission cap per draft-job window (values in `api/_lib/forge-world-limits.js`), answering 429 with `scope` (`player` or `world`) and `retry_after`, which the client reads to say which limit tripped and how long to wait. The client shows the job's real queued state, not a queue position. Verify the 429 path from two tabs.

## Verify

- On `npm run dev` with a second browser: generate a prop from a prompt, see the hologram, see the swap, confirm the second browser renders it live and after a reload (persistence).
- Failure path exercised (kill the request in devtools): error marker, retry works, dismiss cleans up, budget not consumed by the failure.
- Generate an intentionally heavy prompt and confirm the size ceiling triggers with its designed message.
- Mobile emulation: the Forge tab is usable with the touch keyboard and the placed result stays within the memory budget. `npm test` green.

## Report format

Files shipped, the size ceiling values and where they are enforced, the rate-limit shape, average observed generation time during verification, and the `data/changelog.json` entry.
