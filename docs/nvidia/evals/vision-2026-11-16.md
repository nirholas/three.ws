# Vision eval, 2026-11-16: Nemotron VL models on the real consumer tasks

Chain after the change, per NIM key: super-vl, bolt-e4b, nano-omni (thinking off on all three), then the free

evaluation until it is deployed to production.

## Method

- **Eval set.** 66 licence-clean images and 162 graded tasks in
  [data/evals/vision/manifest.json](../../../data/evals/vision/manifest.json). Every image's source and licence is in
  [provenance.json](../../../data/evals/vision/provenance.json): 33 CC0 Poly Haven models rendered by three.ws,
  28 CC0 or public-domain Wikimedia Commons photos, 2 darkened derivatives of those, and 3 screenshots of three.ws pages.
- **Tasks are the consumers.** Each task sends the exact production prompt, imported from the consumer module, with
  the consumer's token cap, and is scored the way that consumer acts on the reply:

  | Task | Consumer | What is scored | n |
  |---|---|---|---|
  | caption | `api/_lib/avatar-alt-text.js` | the cleaned alt text names every expected subject group | 21 |
  | describe | `api/_lib/gateway/media.js` | names the subject; exact transcription of any sign or chart text | 16 |
  | forge_precheck | `api/_lib/forge-image-validate.js` | `usable` matches; a rejection gives the expected `issue` (22 usable, 14 to reject across four issue classes) | 36 |
  | image3d_review | `api/_lib/x-mention-image3d.js` | the bot's verdict (ok, unusable, unsafe), with `safe` checked before `usable` like the bot does | 24 |
  | avatar_review | `api/_lib/x-mention-avatar.js` | same, on profile-photo style images | 24 |
  | quality_gate | `api/_lib/forge-quality-gate.js` | the rubric score lands on the right side of the production pass score (10 pass, 5 reject) | 15 |
  | seed_judge | `api/_lib/seed-quality.js` | every rubric axis present; `promptAdherence` separates match from mismatch (8 match, 4 mismatch) | 12 |
  | object_detect | `api/_lib/forge-objects.js` | valid 0 to 1000 boxes and recall of the labelled objects | 9 |
  | diorama | `api/_lib/diorama-photo.js` | mood and ground from the schema enums, valid boxes, recall of the labelled objects | 5 |

- **Parsing is production's.** JSON tasks go through `parseJsonLoose` from `api/_lib/vision.js` after the same
  reasoning stripping, so a reply production cannot parse is a schema miss here too.
- **Same request shape as production.** NIM models get `chat_template_kwargs.enable_thinking: false`, the base64
  image the consumer would send, and a 90 s ceiling. "In budget" also requires the reply to land inside the consumer's
  own per-attempt budget.
- **Throttling.** Six requests in flight on the NIM host, spaced 1.7 s, with 15/30/60/120 s backoff on a 429.
- **Tie threshold.** A candidate within 2 points of in-budget accuracy of the best on a task ties, and the faster
  p50 wins the tie.
- **Input modes.** One alarm-clock image as base64 at 1024 px and as a public https URL, a 3072 px base64 image,
  and two images in one request.

## The Cloudflare Workers AI rung is dead in production

The forge quality gate and the catalog seed judge both led with Workers AI Llama 4 Scout
(`QUALITY_GATE_VISION_LEAD`, and the seed judge's own lead), chosen on 2026-09-30 when the NIM 11B model narrated
instead of answering JSON. The production token behind it (`CLOUDFLARE_AI_API_TOKEN`, Secret Manager
`agent-cloudflare-api-token` version 1, created 2026-09-16) now fails `/user/tokens/verify` with
"Invalid API Token", and Workers AI answers `10000 Authentication error`. Every gate and judge call in production
has therefore been paying a 401 before falling through to the NIM rung. Both now lead with the NIM model that won
their task in this eval (bolt-e4b for the gate, super-vl for the seed judge), and Scout stays in the chain behind
the NIM lane as a fallback. Scout could not be re-measured for this reason; it is listed as unscored above, not as
a loser. The owner step is to issue a new Workers AI token and add it as a new secret version; re-running
`npm run nvidia:vision-eval -- --models cf-scout --date <day>` then scores it on the same set.

## Input handling and limits

- **Reasoning.** All three NIM models are reasoning models. The chain sends
  `chat_template_kwargs: { enable_thinking: false }`, and `stripReasoning` removes any `<think>` block (closed,
  unclosed, or with the opening tag eaten by the template) before a consumer sees the text. In this run 0 replies
  carried inline thinking.
- **URL vs base64.** All three answered an https URL, a 3072 px base64 image and a two-image request (table
  above). bolt-e4b misread the URL probe ("Chrome bicycle handlebar detail" for an alarm clock) while reading the
  same image correctly as base64, so the chain keeps fetching a caller's URL itself (SSRF-guarded, 12 MB cap) and
  sends base64, falling back to URL pass-through only when it cannot fetch the image.
- **Size and count.** Consumers send one image per call, and every model in the chain accepted two. Inputs are
  bounded by bytes, not pixels (12 MB for a fetched URL, 700 KB for an inline diorama photo, 16 MB for a quality
  gate render), and all three models accepted a 3072 px image, so no resize step is needed for correctness. Large
  images do cost latency: the 3072 px probe took bolt-e4b 6.6 s against 3.2 s for super-vl and 1.3 s for nano-omni.
- **Seed-judge JSON.** 9 of super-vl's 12 seed-judge replies leave the free-text `critique` unquoted. Production's
  judge already repairs that shape (`parseJsonReply` in [api/_lib/seed-quality.js](../../../api/_lib/seed-quality.js)),
  so the scorer reads those replies with the same function. Doing so surfaced a bug in the repair itself: it also
  quoted every number, boolean and null in a repaired reply. That is fixed and covered by
  [tests/seed-quality-json-repair.test.js](../../../tests/seed-quality-json-repair.test.js).
- **Failover, observed live.** During the first dev-server verification pass, super-vl answered one object
  detection call with a 503 and the chain moved to bolt-e4b in the same request, which answered in 3.8 s total.
