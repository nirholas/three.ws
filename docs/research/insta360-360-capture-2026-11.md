# Insta360 and 360 capture on three.ws: every option, evaluated (2026-11-21)

**Question:** can three.ws let people use their Insta360 cameras, files, or editor plugins to build 3D on the platform?

**Answer: yes, and three.ws already has about half of the pipeline.** The missing half is a 360 front end (stitch or split the footage into views a reconstructor can use) and a splat-training lane. No Insta360 SDK license is required for any of the recommended steps. Every core component is MIT, Apache-2.0 or BSD.

The biggest market fact: Insta360 launched its own Gaussian-splat feature, **Spatial Capture**, with the X6 on 2026-08-12. It is app-only and cloud-processed by a third party (the KIRI Engine team). The free tier is four scenes a month, and you cannot download the splat file, only a video or a share link ([Radiance Fields](https://radiancefields.com/insta360-brings-gaussian-splatting-to-the-x6-with-spatial-capture), [Splats News](https://www.splats.com/2026/08/12/insta360-x6-spatial-capture), [Camera Jabber](https://camerajabber.com/photography-news/insta360-x6-turns-360-video-into-explorable-3d-scenes-with-spatial-capture/)). The three.ws pitch is the opposite: **you own the file** (PLY/SPZ/GLB), your avatar can walk in it, an agent can live in it, and it embeds anywhere.

Research method: three parallel sweeps (file formats and SDKs; 360-to-3D reconstruction; editor plugin hosts) over GitHub, npm, PyPI, crates.io, arXiv, Hugging Face, vendor docs and forums. The load-bearing claims (COLMAP spherical support, the GyroView package, Spatial Capture limits, npm package metadata) were re-checked against primary sources. Items marked **unverified** could not be confirmed from a primary page.

## 1. What three.ws already has

| Piece | Where | Relevance to 360 |
|---|---|---|
| Video to point cloud (LingBot-Map, Apache-2.0) | [workers/model-video2scene/](../../workers/model-video2scene), [api/scene-capture.js](../../api/scene-capture.js), page `/capture` | Takes a pinhole video today. Needs 360 footage split into perspective views first. Upload cap is 512 MB ([api/_lib/anon-upload-limits.js](../../api/_lib/anon-upload-limits.js)), which fits roughly 30 to 60 s of 8K. Not deployed (`GCP_VIDEO2SCENE_URL` unset). |
| Gaussian splat viewer | `/splat`, [src/splat-viewer.js](../../src/splat-viewer.js) | Already renders `.ply/.spz/.splat/.ksplat/.sog`. The output end of a 360-to-splat pipeline is done. |
| Video to motion (MediaPipe) | `/video-to-motion`, `/motion-swap`, [workers/model-video2motion/](../../workers/model-video2motion) | A 360 clip can be reframed to a perspective view of the subject and fed straight in. Insta360 users film themselves constantly (invisible selfie stick). |
| Equirect environment lighting | [src/viewer/environment.js](../../src/viewer/environment.js) | Uses `pmremGenerator.fromEquirectangular`, but only loads preset EXRs. A user's own 360 photo as the avatar environment is a small change. |
| Blender extension | [integrations/blender/](../../integrations/blender) (listed on extensions.blender.org) | The landing zone for 360-derived meshes and splats. |
| Unity, Unreal, Godot bridges, ComfyUI nodes | `packages/unity-bridge`, `packages/unreal-bridge`, `packages/godot-bridge`, `integrations/comfyui` | Precedent for host plugins that call the three.ws API. |
| MCP server and HTTP API | `packages/mcp`, `api/` | Any new lane is automatically reachable from agents and plugins. |

## 2. What Insta360 users actually have

| Asset | Format | Notes |
|---|---|---|
| Raw 360 video | `.insv`: an mp4 plus an appended binary trailer | Dual fisheye, unstitched. X4, X5 and X6 write one file with two square tracks (one per lens); X3 writes a `_00_`/`_10_` pair at 5.7K. A plain player shows one lens. ([raw360-formats](https://github.com/freeKC/raw360-formats/blob/main/docs/insta360.md), [Media SDK docs](https://insta360develop.github.io/Insta360-Developer_Docs/en/x/desktop/media/)) |
| Raw 360 photo | `.insp`: JPEG plus trailer, both fisheye circles side by side | Also DNG raw on recent models. |
| Proxy | `.lrv`: low-res H.264, same trailer | Useful for fast previews and upload-light flows. |
| Metadata in the trailer | Protobuf metadata, IMU (gyro and accel), exposure, GPS, **per-unit lens calibration** (equidistant on old models, Mei unified model on X3/X4, Mei with five radial terms on X5) | Not officially documented. Reverse-engineered by the community. The calibration is what makes a good stitch possible without Insta360's SDK. |
| Stitched export | Equirectangular mp4 or jpg (2:1, up to 8K: 7680x3840 on X5/X6) from Insta360 Studio or the phone app | Zero integration needed: the user exports and uploads. ([ThingLink guide](https://support.thinglink.com/hc/en-us/articles/360035962953-How-to-convert-360-media-from-Insta360-cameras)) |
| Action-cam footage | Ace Pro, GO 3: normal mp4 | Already works on `/capture` and `/video-to-motion` today. |

## 3. Ingest options (getting usable pixels out of Insta360 files)

| Option | License | Verdict |
|---|---|---|
| **Accept stitched equirect exports** (mp4/jpg from Studio or the app) | n/a | **Do first.** Works for every model, zero risk. Detect 2:1 aspect plus spherical metadata and route to the 360 lane. |
| **[@bubo-squared/gyroview](https://github.com/bubo-squared/GyroView)** (npm, v0.10.1, published 2026-11-11) | MIT | Plays and stitches raw `.insv` in the browser from factory calibration in one WebGL2 pass, gyro-stabilized. Verified on real X5 files plus one file each from X3, X4 Air, X6, ONE R, ONE RS. **No frame-export API**, and hardware HEVC is required (8K needs a Level 6 decoder; Linux Chrome needs VA-API). Best use: an instant, local "drop your .insv" preview on three.ws before upload. To extract frames we would read its canvas or fork its stitch shader (MIT allows both). 11 stars, single maintainer. |
| [@cradgear/insta360-stitch](https://github.com/rgryta/insta360-stitch) (npm/crates/PyPI, v0.0.3) | MIT OR Apache-2.0 | Rust stitcher using the X5 v6 calibration. X5 only, brand new. A candidate for a server-side stitch step; watch, don't depend. |
| [alexvaut/insv-stitch](https://github.com/alexvaut/insv-stitch) | MIT | Python, optional CuPy. X5. Reports about 22.7 dB PSNR against Studio at 7680x3840. Fits a Python GPU worker. |
| [AdrianEddy/telemetry-parser](https://github.com/AdrianEddy/telemetry-parser) (Rust, PyPI `telemetry-parser-py`) | Apache-2.0 / MIT | The gyro/IMU parser behind Gyroflow. Reusable commercially. IMU only, no stitching. Gives us camera orientation priors for SfM and horizon leveling. |
| ffmpeg `v360=dfisheye:equirect` | LGPL/GPL build-dependent | Uncalibrated. Visible seam, parallax, tilted horizon. Preview-grade only, never reconstruction input. |
| **Insta360 Media SDK** (C++, Windows and Ubuntu 22.04, CUDA) | Proprietary EULA, apply at insta360.com/sdk/apply | Best stitch quality (template, dynamic, optical-flow, AI modes) and covers ONE X through X6. A Linux server stitch in Docker is demonstrated by the community. **Server-side and commercial redistribution terms are unverified**: the EULA page returned 403 and older guidance requires an NDA and a business license. Upgrade path only, after written confirmation from enterprise@insta360.com. |
| Insta360 Camera SDK / OSC Wi-Fi API | Proprietary / open docs | Camera control and file download over Wi-Fi (192.168.42.1). Useful later for a "shoot straight to three.ws" mobile flow; irrelevant to stitching. |
| Gyroflow | GPL-3.0 | Do not link (copyleft). Its parser dependency is the reusable part. Gyroflow does not support 360 cameras anyway. |

## 4. Reconstruction options (360 pixels to 3D)

### 4a. Walkaround video to Gaussian splat scene (the headline feature)

| Rank | Pipeline | License | Assessment |
|---|---|---|---|
| **1** | Split each equirect frame into 8 to 14 perspective views (ffmpeg/OpenCV), solve poses with **COLMAP 4.2 rig support** (`panorama_sfm.py`, global mapper), mask the operator, train with **gsplat** or **Brush** | BSD / Apache-2.0 | The same shape as every commercial 360 splat tool (360 Gaussian Pro, Postshot workflows), so quality is proven. COLMAP's own notes say rendering perspective views is more accurate than its native spherical model ([releases](https://github.com/colmap/colmap/releases)). Minutes to tens of minutes on an L4. Output drops straight into `/splat`. |
| 2 | COLMAP 4.1+ **native spherical camera** for poses, then train on splits or with [gsplat360](https://github.com/zcq15/gsplat360) (equirect rasterizer fork) | BSD / Apache-2.0 | Faster SfM, less accurate. gsplat360 has 7 stars and no training script; it needs hardening. |
| 3 | Cubemap or rig faces into **LingBot-Map** (already built) or MapAnything-Apache for fast poses and dense init | Apache-2.0 | Reuses `workers/model-video2scene`. Nothing documents 360 behavior, so this is an untested preview lane, not the final pipeline. |

**Licensing traps (avoid without a commercial agreement):** the Inria 3DGS line and its forks (360-GS, splatfacto-360, inuex35/360-gaussian-splatting), OmniGS (GPL-3.0), ODGS-SLAM, VGGT's original checkpoint, Pi3, MASt3R/DUSt3R, Fast3R, UniK3D, and Insta360's own **DAP** panorama-depth model (CC BY-NC 4.0). OpenDroneMap's OpenSfM fork is AGPL; the Mapillary upstream is BSD and supports spherical cameras natively.

### 4b. One 360 photo to an explorable scene

| Rank | Pipeline | License | Assessment |
|---|---|---|---|
| 1 | **[MoGe-2](https://github.com/microsoft/MoGe)** `infer_panorama` (metric depth from a real equirect photo) to a colored point cloud or mesh shell | Code MIT; weight license to confirm on the Hugging Face card | Works on real photos, commercial-friendly. Result is a 2.5D shell: strong parallax near the capture point, holes when you walk away. Good for "stand inside your photo" and as an avatar backdrop with depth. |
| 2 | World Labs Marble API with `is_pano` | Paid third-party | Best quality, exports SPZ/PLY plus a collider GLB, hallucinates unseen regions. New paid external API: needs owner approval per CLAUDE.md. |
| Skip | HunyuanWorld 1.0 / HY-World 2.0 | Tencent license | Excludes EU, UK and South Korea, and bars training on outputs. Generative; not faithful to a real capture. |

### 4c. Other high-value uses that need little new infrastructure

| Use | Effort | Notes |
|---|---|---|
| **Your 360 photo as the avatar's environment and backdrop** | Small | Extend `src/viewer/environment.js` to accept a user JPG/HDR equirect (it currently loads preset EXRs only). An 8-bit JPG gives soft lighting; a bracketed X5 DNG merged to EXR gives real HDR. |
| **360 video to motion capture** | Small to medium | Reframe a perspective view that tracks the subject, then call the existing video2motion worker. Turns every "invisible selfie stick" clip into an animation for your avatar. |
| 360 video as an animated skybox | Small | Plain three.js video texture on a sphere. |
| Gyro path as a virtual camera | Medium | telemetry-parser gives the real camera path; replay it inside a three.ws scene for cinematic renders. |

## 5. Editor and host plugins

| Host | Tech | Insta360 audience | Verdict |
|---|---|---|---|
| **Insta360 Studio / app** | No plugin API found; no partner program found | All of them | Not a target. The route is "export, then upload", or the Media SDK later. |
| **Blender** | Python add-on, we already ship one | 3D landing zone | **Extend the existing extension:** "Reconstruct from 360 video" plus import of the returned GLB or 3DGS `.ply` (the free Apache-2.0 [KIRI 3DGS Render add-on](https://github.com/Kiri-Innovation/3dgs-render-blender-addon) renders splats in Blender 4.2+). Lowest effort, existing distribution. |
| **Premiere Pro (UXP)** | JS/HTML panel; UXP is GA since Premiere 25.6; declared network domains, fetch and filesystem access ([Adobe UXP network](https://developer.adobe.com/premiere-pro/uxp/resources/recipes/network)) | High: Insta360's own **Reframe** plugin already brings `.insv` into Premiere ([Insta360 blog](https://www.insta360.com/blog/news/insta360-reframe-adobe-premiere-pro-plugin.html)) | **Best reach for editors.** Panel sends the selected 360 clip to three.ws and returns a splat flythrough render or GLB. After Effects 24.1+ imports GLB natively, so the 3D comes back into the Adobe world. CEP is being retired (no new submissions from December 2027), so build UXP only. Medium effort. |
| DaVinci Resolve | Workflow Integration (Electron), scripting | Medium | Defer. Plugins and external scripting are Studio-only, Fusion has no native GLB import (we would ship FBX/USD), and free-tier scripting is shrinking (reported, unverified). |
| Final Cut Pro | FxPlug 4 / workflow extensions, Swift, Mac App Store | Medium | Defer. High effort, Mac-only. |
| Gyroflow | GPL-3.0 OpenFX/Adobe/FCP plugins | Stabilization users | Not a host. Reuse telemetry-parser only. |
| CapCut, Canva, GoPro Quik, DJI | No verified editing plugin API (CapCut); 2D-only apps (Canva) | Low | Skip. |
| Unity / Unreal / Godot | Existing three.ws bridges | Low for Insta360 users | Already covered; add splat import when the lane ships. |
| **MCP** | Existing server | Agents | Free: once the 360 lane exists, expose it as a tool so any agent can turn a 360 file into a scene. |

Precedent: every AI-3D plugin found (Meshy, Tripo, KIRI, Luma, Postshot) follows the same pattern: sign in or paste an API key, send the asset, import the result as a native file. Most ship outside the official marketplaces.

## 6. Recommended build order

| Phase | Deliverable | Depends on | Effort |
|---|---|---|---|
| 1 | **360 photo to avatar environment and backdrop**: upload an equirect JPG/EXR on the avatar viewer and `/splat`; also MoGe-2 depth shell as an option | Viewer change; one CPU/GPU worker for MoGe-2 | Days |
| 2 | **`/capture` 360 mode**: accept stitched equirect video, split to a perspective rig server-side, run COLMAP 4.2 rig SfM, train gsplat on an L4, return PLY/SPZ into `/splat`. Same job API shape as `api/scene-capture.js` | New worker (`model-pano2splat` or a 360 mode in `model-video2scene`); GCP GPU pre-approved | 1 to 2 weeks |
| 3 | **Raw `.insv` support**: GyroView local preview plus trailer parse (model, calibration, gyro) in the browser; server stitch with the calibration (insv-stitch / insta360-stitch, or our own Mei-model remap); gyro priors into SfM | Phase 2 | 1 week |
| 4 | **360 video to motion**: subject-tracking reframe feeding the existing video2motion worker | Existing worker | Days |
| 5 | **Plugins**: extend the Blender extension (360 upload, splat import); then a Premiere UXP panel with GLB return to After Effects; expose the lane as an MCP tool | Phase 2 API | 1 week each |
| Later | Insta360 Media SDK server stitch, OSC "shoot to three.ws" from the phone | Written EULA confirmation from Insta360 | n/a |

Positioning against Spatial Capture: no monthly scene cap tied to one app, a downloadable PLY/SPZ/GLB, works with X3 and older plus any other 360 camera's equirect export, and the scene becomes a place on three.ws (avatar walkabout, agent home, embed) instead of a video share link.
