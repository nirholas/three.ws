# Microsoft Reactor session proposal: a Copilot Studio agent that builds a speaking 3D character

**Status:** proposal, not submitted. Submitting it to a Microsoft Reactor team is an owner step. The rehearsal timings below were measured on 2026-11-12; re-run the rehearsal before submitting and again on the day.

## Title

Build a Copilot Studio agent that turns a sentence into a rigged, speaking 3D character

## Abstract

Most MCP demos return text. This one returns something you can walk around. In 45 minutes we build a Copilot Studio agent from an empty canvas, connect it to the free three.ws MCP server with the Model Context Protocol onboarding wizard (no key, no account), and ask it for a 3D prop and then a character. The agent calls the tools, polls the GPU jobs, and hands back interactive 3D models generated by TRELLIS from Microsoft Research on NVIDIA L4 GPUs. We then turn the character into a named agent persona that speaks, and drop it into a web page and a Teams tab with one HTML tag. Everything shown is open source (Apache-2.0) and every tool call is live against production.

three.ws and Microsoft have announced a partnership, and three.ws is live on Microsoft Marketplace.

## Audience

- Copilot Studio makers who have built a topic-based agent and want to add tools.
- Developers evaluating MCP servers for Copilot Studio, Microsoft 365 Copilot or Foundry.
- Teams and web developers who want a visual agent rather than a text box.

Level: intermediate (200). No 3D experience needed.

## Learning outcomes

By the end, attendees can:

1. Connect a Copilot Studio agent to a remote MCP server over the Streamable transport with the onboarding wizard, and write a server description the orchestrator can route on.
2. Handle long-running tools in an agent: a tool that returns a job, and a second tool that polls it.
3. Explain what TRELLIS does in an image-to-3D pipeline and what the quality tiers cost in wall time.
4. Turn a generated character into an agent persona with a voice, and embed it with the `<agent-3d>` web component or a Teams tab.

## What the presenter needs

- A Copilot Studio environment whose data policy allows custom MCP connectors. Access to MCP servers in Copilot Studio goes through Power Platform connectors, so a tenant data policy that blocks custom connectors also blocks this demo ([Microsoft Learn: MCP servers and data policies](https://learn.microsoft.com/en-us/microsoft-copilot-studio/mcp-add-existing-server-to-agent#mcp-servers-and-data-policies)).
- A terminal with this repository checked out and Node 22 or later, for the rehearsal and the fallback.
- Browser tabs: Copilot Studio, the three.ws viewer, a blank HTML page served locally, and the agent tab at `https://three.ws/microsoft/teams-tab`.

## Run-of-show (45 minutes)

The two generations are the long beats, so each one is started early and the talk fills the wait. The deadlines carry margin over the measured rehearsal (see [Measured rehearsal](#measured-rehearsal)); when a deadline passes, switch to the fallback for that beat without apology and keep going.

## Demo script

**Wizard values** (step 5 of Microsoft's [MCP onboarding wizard](https://learn.microsoft.com/en-us/microsoft-copilot-studio/mcp-add-existing-server-to-agent#option-1-use-the-mcp-onboarding-wizard-recommended), click path verified on 2026-11-12):

| Field | Value |
|---|---|
| Server name | three.ws |
| Server description | Generates textured 3D models and rigged 3D avatars from a sentence, polls generation jobs, inspects finished models, searches a free catalog of ready-made 3D assets, and turns a character into a speaking agent persona. Call it when the user asks for a 3D model, prop, character or avatar. |
| Server URL | `https://three.ws/api/mcp-studio` |
| Authentication | None |

Copilot Studio supports only the Streamable transport for MCP; the three.ws endpoint is Streamable HTTP, so nothing else needs configuring.

**Lines to type in the test pane**, in order. These are the prompts the rehearsal script sends, so the rehearsal timings apply:

1. `Make a 3D model of a brass desk lamp with a green glass shade. Use draft quality.`
2. `Look at the model you just made and tell me what you see.`
3. `Now make a rigged 3D character: a friendly lighthouse keeper in a yellow raincoat.`
4. `Turn that character into an agent persona called Keeper.`
5. `Have Keeper say: Welcome aboard. The light has not missed a night in forty years.`

If the agent answers a generation request with a job and no model, type `Check on that job.` and it calls `get_job` (or `check_job`) with the id it holds.

**Embed snippet** for the 35:00 beat. Replace the `body` value with the character's GLB URL from line 3 (or from the fallback):

```html
<script type="module" src="https://unpkg.com/three.ws"></script>
<agent-3d
  body="https://three.ws/avatars/realistic-female.glb"
  brain="free"
  instructions="You are Keeper, a friendly lighthouse keeper. Answer in two sentences."
  style="width: 420px; height: 560px; display: block;"
></agent-3d>
```

## Preflight (60 to 90 minutes before going live)

1. Run the rehearsal: `node scripts/microsoft-pack/rehearse-reactor-demo.mjs`. It sends the same five calls to the production endpoint and prints a table of timings, the two GLB URLs and the persona id. Exit code 1 names the failing step and the server's reason.
2. Open both GLB URLs in the viewer (`https://three.ws/viewer?src=<url-encoded GLB URL>`) and keep the tabs. These are the fallback assets, generated by the same tools from the same prompts that day.
3. Put the character GLB URL into the embed snippet, save the page, and keep it open: this is the 00:00 opener and the 35:00 fallback.
4. In the demo tenant, record the screen, add the MCP tool once and send line 1. We have not measured how long Copilot Studio waits on a single tool call, and the rehearsal's first `forge_free` response took 220 s, so confirm here whether the agent shows the job or times out. If it times out, run the generations in the preflight and, live, use lines 1 and 3 to show the tool call being made, then continue with the preflight assets.
5. Compare the rehearsal's times to the deadlines. If a generation took longer than its window (8 minutes for the prop, 8 minutes for the character), start that generation from the terminal at 00:00 so it is finished when its beat arrives.

## Fallbacks

| When | Do this | Say |
|---|---|---|
| Fallback 1: no prop link at 21:00 | Open the preflight lamp tab. Leave the live job running and open its link at the end if it lands. | "The GPU queue is busy right now; here is the same request from an hour ago, made the same way." |
| Fallback 2: no character link at 31:00 | Open the preflight character tab and use its GLB URL for lines 4 and 5 and the embed. | Same as above. |
| A tool call fails with a lane message | The Forge pauses a failing lane for 90 seconds (`LANE_COOLDOWN_SECONDS` in `api/_lib/forge-lane-health.js`). Carry on talking and send the line again after 90 seconds; meanwhile use the preflight asset. | "The service just took a GPU lane out of rotation for a moment; that protects the queue." |
| Copilot Studio cannot reach the server | Show the same calls from the terminal with the rehearsal script, which prints the same results. | "Same server, same calls, from a terminal." |
| No network on stage | Play the screen recording of the preflight run, made in step 4. | "Here is the run from this afternoon." |

## Measured rehearsal

Run on 2026-11-12, starting 16:30 UTC, with `node scripts/microsoft-pack/rehearse-reactor-demo.mjs` against `https://three.ws/api/mcp-studio`. All five steps passed.

| Step | Total time | First response | Result |
|---|---|---|---|
| `tools/list` | 0.4 s | | 16 tools |
| `forge_free`, draft tier, "a brass desk lamp with a green glass shade" | 302.0 s | 220.1 s | GLB, 217,140 bytes |
| `forge_avatar`, "a friendly lighthouse keeper in a yellow raincoat" | 395.7 s | 228.4 s | Rigged GLB, 3,601,412 bytes |
| `create_agent_persona`, name Keeper | 3.0 s | | persona created |
| `persona_say`, one line | 0.5 s | | spoken, emotion `neutral` |

The draft generation took 302 s here against a 30-day production median of 132 s for completed draft TRELLIS jobs (see [sources.md](./sources.md#trellis-on-our-gpus-one-pager-tech-community-trellis-gpusmd-deck)). The run-of-show windows are sized to the slower figure, and the preflight exists because the queue on the day is what decides.
