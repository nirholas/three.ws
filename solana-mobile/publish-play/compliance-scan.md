# Google Play compliance scan: `ws.three.app` 1.1.0

Scanned 2026-11-22 with the open source [App Store Compliance Playbook](https://github.com/mjmirza/app-store-compliance) (rule pack v2.5.0, 111 dated sources, newest verified 2026-11-21). The playbook is a static, local scan of code, manifests and listing copy. It does not see Play Console state and does not guarantee approval.

## Re-run it

```bash
git clone --depth 1 https://github.com/mjmirza/app-store-compliance ~/repositories/app-store-compliance
bash ~/repositories/app-store-compliance/agent-os/hooks/app-store-compliance-guard.sh "$PWD/solana-mobile/build"
```

`solana-mobile/build` is the Bubblewrap project after `scripts/apply-overlay.mjs` (it is gitignored and regenerated by `scripts/build-apk.sh`). The guard reads files and writes only temp files. It makes no network calls.

## Verdict

**CLEAR: 0 critical.** The first pass found 5 high and 1 medium. One high was real and is fixed (below). The other four are false positives or already mitigated, each checked against the source.

| Finding | Severity | Status | Evidence |
|---|---|---|---|
| ANDROID-INSECURE-BACKUP: `allowBackup="true"` with no rules | High | **Fixed** | Bubblewrap emits `allowBackup="true"`, so the glance widget's bearer token (`glw_…` in SharedPreferences `glance_widget`) was copied into Google Drive backups and onto any phone restored from them. `apply-overlay.mjs` now points `<application>` at `glance_backup_rules.xml` (API 30 and below) and `glance_data_extraction_rules.xml` (API 31+), which exclude the token and the card cache from cloud backup and device transfer. Covered by `tests/solana-mobile-apply-overlay.test.js`, and `gradlew :app:processReleaseResources` compiles the merged manifest. Ships in the next `build-apk.sh` build. |
| BOTH-SECURE-STORAGE: credentials in plain SharedPreferences | High | Accepted | The only credential is the widget token: read-only (it fetches one card image), revocable at three.ws/glance, held in `MODE_PRIVATE` app storage, and now kept out of backups. The guard cites `src/debug/AndroidManifest.xml:4`, which is a comment. The real hit is `GlanceStore.java:43`. |
| BOTH-UNSAFE-DEEPLINK: `threews://glance` without App Links | High | Mitigated | On Android, `api/glance/token.js` launches the link as `intent://…#Intent;scheme=threews;package=ws.three.app;end`, so Chrome delivers it only to our package. The bare `threews://` form exists for the Apple apps. The https deep link is App-Links verified (`autoVerify="true"`, live `assetlinks.json`). |
| ANDROID-RUNTIME-PERMISSIONS: `RECORD_AUDIO` not validated | High | False positive | `DriveScreen.java` checks `checkSelfPermission(RECORD_AUDIO)`, requests it through `CarContext.requestPermissions`, and shows a dedicated "microphone needed" screen when it is denied. |
| GOOGLE-MISSING-PRIVACY-POLICY | High | False positive | A TWA has no privacy URL in code. It is set in Play Console: `config.yaml` has `privacy_policy: https://three.ws/legal/privacy` (live, 200). |
| GOOGLE-12-TESTER-RULE | Medium | Owner | Personal accounts need 12 testers opted in for 14 days. Organization accounts are exempt. See [README.md](README.md#the-one-decision-that-sets-the-timeline). |

The listing audit (`scripts/metadata-audit.py --platform google`) ran on `listing/title.txt`, `short-description.txt` and `full-description.txt` and found no title, length, claim or keyword problems. It also flagged a missing contact email. That email is entered in Play Console from `config.yaml` (`support@three.ws`), so it is a false positive.

## Play Console items a code scan cannot see

1. **Foreground service declaration.** The app declares `FOREGROUND_SERVICE_MICROPHONE` and `FOREGROUND_SERVICE_MEDIA_PLAYBACK` (`DriveWebService`, Android Auto voice) and targets API 36, so Play Console requires App content > Foreground service permissions, with a short video. The wording is in [README.md](README.md#foreground-service-declaration).
2. **Play App Signing fingerprint.** `twa/extra-fingerprints.json` is still empty. The first Play upload produces Google's signing key, and its SHA-256 must be added there, then `assetlinks.json` redeployed, or Play installs lose full-screen mode (README step 6).
3. **Financial features declaration.** See [listing/financial-features.md](listing/financial-features.md).
