## Why this matters

The owner's `UCAI` turns verified EVM contract ABIs into MCP servers, with a security scanner. It is EVM and Python only, and Anchor IDL support sits on its roadmap. Solana first means we build the Anchor path ourselves: read accounts, preview instructions, and route writes through the wallet confirm flow. Our own IDLs in `contracts/idl/` (`skill_license.json`, `agent_invocation.json`) are perfect first fixtures. Builds on order 524's importer.

## Tasks

1. An IDL importer (inside `packages/skill-import` if 524 shipped, else a new module the 524 package will absorb): for each account type a read tool that fetches and decodes by address; for each instruction a preview tool that builds the instruction and returns accounts, data and a human summary without signing.
2. Write tools hand off to the existing confirm-gated signing flow (the same one agent wallets use) and are marked `destructiveHint: true`.
3. A UCAI-style risk panel: flags instructions that move tokens, close accounts, or change authorities.
4. `POST /api/skills/import` accepts `{ idl_url | program_id }` (program ID fetches the on-chain IDL account).
5. Docs and changelog.
