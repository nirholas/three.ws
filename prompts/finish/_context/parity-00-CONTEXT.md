The teardown is [docs/research/competitor-teardown-2026-09.md](../../../docs/research/competitor-teardown-2026-09.md). Its bottom line: we already have most of the technology. Competitor X wins on packaging (one connector URL, one CLI command, the fee flow explained per $100) and on proof (earnings, analytics, stories, published experiments). Every `parity-` order closes one of those gaps with real data.

## Facts every order relies on

- **$THREE** mint `FeMbDoX7R1Psc4GEcvJdsbNbZA3bfztcyDCatJVJpump` on Solana. It is the only coin the platform promotes.
- **The platform never burns $THREE.** Policy is in code: [api/_lib/token/config.js](../../../api/_lib/token/config.js) (`SPLIT_POLICIES`, no burn leg; the treasury funds buybacks). The "buyback and burn" in `api/cron/launcher-claimer.js` is about each agent's OWN coin through pump.fun's buyback vault, not $THREE. Never write copy that says $THREE is burned by the platform.
- **Public token config:** `GET /api/token/config` returns the mint, the treasury and rewards wallets, and every split policy in basis points. Read numbers from it; never type them into page copy.
- **Solana first.** Build and verify on Solana before any EVM leg (CLAUDE.md "Solana first").
- **Spend gate.** Anything that pays, launches, transfers or settles shows amount, asset, chain and recipient and waits for an explicit yes. Launching signs with the agent's custodial wallet and is allowed only from a same-site browser session (`requireSessionUser` in `api/pump/[action].js`); do not add a bearer-token launch path.
- **Commit gate.** Committed files never name Competitor X; say "Competitor X" if a reference is unavoidable. Anything naming another crypto project needs the owner's yes before commit.
- **Numbers on pages come from live APIs.** Competitor X's pages contradict themselves (two revenue-share figures, six tool counts). Every figure we publish is fetched at render time or generated at build time, with a "how it's calculated" line.

## How a new page is wired (all five, every time)

1. The page: `pages/<name>.html` (copy the head block, theme boot script, `nav.js` header and `/i18n.js` tail from [pages/connect.html](../../../pages/connect.html)). Colors and spacing come from the tokens in `public/tokens.css` / `public/style.css`.
2. The route: a `{ "src": "/<name>/?", "dest": "/<name>.html" }` row in `vercel.json`, near a sibling page.
3. The build input: a `<name>: resolve(__dirname, 'pages/<name>.html')` line in `vite.config.js`.
4. The index: an entry in `data/pages.json` with `path`, `title`, `description`, `priority`, `changefreq`, `added`, then `npm run build:pages`. This feeds the sitemap, `llms-full.txt`, `features.json` and the changelog automatically.
5. The map: a row in `STRUCTURE.md`. Nav entries go in `public/nav-data.js`; the lite (first-visit) menu is capped at 30 items by `tests/onboarding-tier.test.js`, so new items default to `tier: 'advanced'` unless one is removed.

Verify in a real browser: `npm run dev` (port 3000; reuse it if another agent is serving), then drive the page with Playwright at 375, 768 and 1440 px in dark and light themes, with zero console errors and every loading, empty and error state exercised. Throwaway Playwright scripts go in `scripts/` with a `.tmp-` prefix and are deleted after.
