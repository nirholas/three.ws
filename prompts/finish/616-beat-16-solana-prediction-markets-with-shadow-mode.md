## Why this matters

Lane D trading. Prediction markets are the fastest-growing agent trading surface. The best open reference runs in shadow mode (decide and log, never trade) until a human approves, and scans for no-arbitrage opportunities after fees. three.ws predictions read Polymarket history only and have no native Solana market venue.

## Tasks

1. **Venue.** Add a Solana prediction-market venue behind the existing venue interface (markets, orderbook or quote, position, redeem). Re-verify the venue's API and any identity requirement from its primary docs in step 0.
2. **Shadow mode.** Every agent's prediction strategy defaults to `shadow`: it records the intended trade, size and edge to a shadow ledger with the price at decision time and marks it to market at resolution. Going live is an explicit setting that the owner flips per agent.
3. **No-arb scanner.** For complementary outcomes across venues (or YES+NO on one), compute the fee-adjusted edge and rank; thresholds and fee models are data, not constants.
4. **Dashboard.** Shadow P&L versus what live would have paid, so the owner can judge before enabling.
5. Tests: fee-adjusted edge arithmetic table, shadow mode never calls an order function (assert via a spy on the real module boundary).
