## Why this matters

Lane E to G identity, distribution, launch. In early 2026 hundreds of malicious skills in a large public skill registry were found stealing environment variables and wallet keys. Any registry that lets third parties publish code that touches a wallet needs a scanner. three.ws skills run in a sandbox with a trust policy, but publish-time static analysis is thin.

## Tasks

1. **Static scanner** over `handlers.js` and `tools.json` using a real parser (AST), flagging: access to environment or key material, network calls to hosts not declared in the manifest, dynamic code evaluation, obfuscated strings, instructions in `SKILL.md` that tell the model to reveal secrets or skip confirmation, and excessive permissions versus declared purpose.
2. **Verdicts.** `clean`, `review`, `blocked`; `blocked` cannot be published; `review` is held for moderators with the findings attached.
3. **Rescan.** All existing published skills rescanned once, and every new version on publish.
4. **Author feedback.** Findings with file, line and fix guidance in the publish UI.
5. Test corpus of malicious-pattern skills written for the test.
