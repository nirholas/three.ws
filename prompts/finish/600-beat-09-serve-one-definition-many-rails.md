## Why this matters

Lane C commerce. Agent frameworks now expose a handler as a paid endpoint on several rails from one definition. three.ws marketplace skills are priced per call over x402 only; an agent that speaks A2A or MPP cannot hire them without a custom bridge.

## Tasks

1. **One pricing record.** Skills already carry a price; add `rails: ["x402","mpp","a2a","ap2"]` (default x402 and a2a). The author toggles rails in the publish flow.
2. **Router.** `GET/POST /api/skills/:id/invoke` answers with the correct 402 challenge for the caller's accept header, the A2A task envelope for A2A callers, and an AP2 mandate request when the caller presents a mandate. All settle to the same author/platform split.
3. **Agent card.** The skill's agent card lists every enabled rail with its endpoint.
4. **Receipts.** Whatever rail was used, the call writes the same receipt row.
5. Tests per rail against local counterparties.
