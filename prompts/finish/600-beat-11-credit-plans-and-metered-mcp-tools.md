## Why this matters

Lane C commerce. Payment platforms for agents sell credits and time-boxed plans, gate individual MCP tools behind them, return the credits consumed in each response, and offer metered free trials. three.ws charges each hosted MCP call independently over x402, which is right for strangers and wrong for a regular customer who would rather prepay a bundle.

## Tasks

1. **Plan model.** `mcp_plans` (credits bundle or time window, price, tools covered) and `mcp_plan_balances` per account. Buying a plan is one x402 or checkout payment.
2. **Tool gating.** Each paid MCP tool declares a credit cost (fixed or a function of the result). The dispatcher debits balance before the call, refunds on a tool error, and returns `creditsUsed` and `creditsRemaining` in the result metadata.
3. **Trials.** Reuse the skill trial meter for MCP tools: N free calls per account per tool.
4. **Account UI** (balance, history, buy more) and API.
5. Tests: debit on success, refund on error, exhausted balance falls back to the per-call 402.
