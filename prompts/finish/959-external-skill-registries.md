Skills are our strongest extensibility surface but they are closed: api/skills/community.js serves only our own community-skills/registry.json baked at deploy, there is no runtime import from external registries, and forking works for agents but not skills. The open ecosystem already has dozens of Solana skill repositories (protocol integrations, data, security, infrastructure) in the same SKILL.md format.

Build safe external import. A registry is a GitHub repository or a manifest URL; the importer fetches skills at runtime, caches them (five minutes for the index, content-addressed for bodies), validates the manifest and SKILL.md, shows the permissions and tools the skill requests, scans it (reuse the guardian and policy packages and the skill sandbox limits), and installs only after the owner approves. Show provenance on every skill (source repo, commit, license, author) and pin the commit so an upstream change never silently alters an installed skill; offer an update diff. Skills that request spending, signing or outbound messaging are flagged and run only under the spend gate.

Add skill_fork and skill_publish as MCP tools and a browse view with categories (DeFi, intelligence, social, infrastructure, security, data) and install counts. Check licences before listing. Test with two real public registries and one deliberately hostile skill that must be refused.
