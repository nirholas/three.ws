Reaching the head unit service

The head unit service is not running

This page talks to a small service on this box that owns the USB dongle. It is not answering on .

Start it with systemctl --user start three-ws-head-unit, or npm start in apps/head-unit.

Connect a CarPlay dongle

Plug a Carlinkit CPC200 into a USB port on this box. The phone's CarPlay or Android Auto screen appears here, beside the agent.

Looking for USB ids
1314:1520 1314:1521

Plugged in and still not found? Run lsusb: one of those ids must be listed. If it is, install the udev rule from apps/head-unit/deploy and replug the dongle.

Opening the dongle. It resets itself first, which takes a few seconds.

The dongle is not answering

Unplug the dongle, wait a moment and plug it back in. A dongle that keeps failing usually needs a powered USB port.

Dongle ready. Connect your phone.

Plug the phone into the dongle's cable, or pair over Bluetooth with three.ws and it joins over Wi-Fi.

An iPhone shows CarPlay. An Android phone needs Android Auto enabled for wireless.

Phone connected. Waiting for its first picture.

This browser cannot show the phone screen

It has no H.264 decoder for WebCodecs.

Use Chromium 94 or newer (Raspberry Pi OS ships one). The kiosk launcher in apps/head-unit/deploy starts the right browser.

The agent needs the internet

The phone screen keeps working offline. The agent comes back when this box is online again.
